Why these

1. GPX viewer/inspector plus a hands-on tutorial

  • Evidence: The viewer term has the strongest relevant estimate. Results include browser viewers and desktop/mobile apps, so intent is mixed.
  • Build: Open a GPX locally, show tracks/routes/waypoints, segments and available timestamps, explain invalid coordinates and missing fields, and offer a documented CSV table.
  • Differentiate: Help people understand the file. Search-result descriptions already advertise private/local viewers, so privacy alone is insufficient.
  • Tutorial: “Check a GPX file before importing it.” Use the existing synthetic multi-segment export, a missing-timestamp variant and a malformed example; publish expected output and recovery steps.
  • Expected benefit: A useful discovery page for people already handling location files, with links to Whereday’s recording/export workflows. Traffic and install gains remain unknown.

2. A format-choice article

  • Build: “GPX, KML or GeoJSON: which location file should you keep?” Show the same invented trip in each representation and demonstrate what conversion preserves or loses.
  • Keep it distinct: The existing export reference lists Whereday’s formats. This article answers a cross-tool file-choice question and links that reference and the viewer.
  • Verify: Use format specifications and conversion fixtures. Do not imply Whereday supports every compared format.

3. Timeline JSON inspector plus a formats tutorial

  • Evidence: The exact viewer term has a small estimate, but strong fit with the published import guide. Existing viewers/converters appear in results.
  • Build: Identify only tested Google JSON shapes, summarize available records/date ranges, and explain unsupported structures. Set explicit scope for ZIP files and large archives.
  • Tutorial: “Which Google Timeline JSON file do I have?” Use invented supported/unsupported examples and link the existing import walkthrough.
  • Limit: An inspector cannot recover missing history, prove archive completeness or guarantee native import success.

4. More useful tutorials without duplicate articles

  • Delivered: reusable blank journal template, completed reflection and linked example folder in the existing Obsidian guide.
  • Expand the backup guide with a checked new-phone restoration walkthrough after verifying that exact workflow.
  • Give each new tutorial a concrete starting file, steps, expected result and troubleshooting section.
