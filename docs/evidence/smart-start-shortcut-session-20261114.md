# Session-scoped Shortcut duration and activity hints

Follow-up to the source-only slice, based on PR120 head `d3faede5309648c6a600ae8c3031d01201f62292`. This receipt covers source, runtime-state tests and compiled metadata/resources. It does **not** complete issue60 or verify actual Shortcuts editor, locked/background execution, trigger delivery, GPS behavior or battery cost.

## Contract and actual implementation

| Requirement | Implementation / evidence |
| --- | --- |
| Preserve simple actions and phrases | Same Start Tracking title, `openAppWhenRun=false`, all three original simple phrases in actual compiled App Intents metadata. Source, durationMinutes and activityProfile are all optional. |
| Optional duration | 1–1,440 minutes, finite numbers only. Omission uses the existing Stop After setting. A private, versioned UserDefaults lease binds the original absolute deadline to the actual recording UUID. No global timer preference write. |
| Optional activity profile | Walking/running and cycling set the actual Core Location `.fitness` hint; driving sets `.automotiveNavigation`. Omission/stopping uses `.other`. Distance filter, sampling mode and interval preferences are unchanged. This is not inferred activity or activity-specific sampling/battery tuning. |
| Do not change an existing session | Repeated Start returns an already-active/no-settings-change dialog. It cannot relabel, extend, replace the activity hint or reschedule an active session. A persisted owned session awaiting access is reattached with its original options, not replaced by a later request. |
| Explicit user edits | Editing Stop After deliberately supersedes only the session duration, retains its activity hint and preserves legacy start-relative setting semantics. Stop/erase ends and clears the lease; the next manual recording uses normal defaults. |
| Ownership and restoration | Reattachment verifies the stored owner exists and is open before native monitoring. Missing/invalid owner pointers, malformed/wrong-type/oversized/unsupported-version payloads, deleted owners and expired leases fail closed. Known unrelated stale leases cannot configure a different valid owner. A second open row cannot steal the leased recording. |
| Access/permission ordering | Unresolved access preserves the owned row and deadline without starting native monitoring. The timer still expires that pending request. Known denial ends it. Access resolution before permission or store attachment does not consume the pending request; later readiness reattaches it without extending the deadline or prompting automatically. The real Store observer calls the same tested refresh method. A resolution flag never grants recording access. |
| Queued callbacks | Generation and owner checks prevent old active/pending timer callbacks stopping a later recording or a reattached lease. |
| Peer and Watch compatibility | Accepted peer starts explicitly take manual ownership and discard phone automation options. No new shared/backup fields or entities. The existing Watch Stop After value represents the phone's same absolute deadline. Duration/profile are not transmitted as new peer options; phone stop publication and offline peer delivery retain their existing best-effort semantics. |
| Permissions and billing | Actual intent entitlement check remains; manager independently gates access/permission. Missing permission and rejected starts return existing useful errors. No opt-in or permission prompt from the helper, no billing bypass. |

The private lease uses the existing `Date`/wall-clock model, not a reboot-persistent monotonic clock. Timers are process-local and best effort; the deadline is rechecked on reattachment. This does not promise an iOS wake at the deadline, immediate offline peer stopping, native CarPlay/HealthKit execution or precise battery/runtime limits.

No SwiftData model, public backup format, import admission rule or route sampling preference was added or changed. Legacy/manual starts still cross the original two-argument `SmartStartTracking` interface. New configuration requires a store, and no accepted configuration is saved after a permission/access failure.

## Executed verification

- **26 new session tests** exercise the actual intent helper and LocationManager with isolated defaults, injected monitoring/access/scheduler, real SwiftData and actual Core Location activity-type property reads. They cover bounds/nonfinite input, profiles, omission, active idempotence, explicit edits, peer takeover, stale callbacks, real SQLite reopen, expired/corrupt/missing/deleted owners, duplicate rows, unresolved versus denied access, permission/store ordering, and pending expiry. They do not measure real sensor delivery or native UI.
- Runtime REDs during implementation caught unsafe prototype versions: missing owner fallback (one method/one failure); four owner/access cases (15 failed assertions including two failed unwraps); missing pending expiry (two methods/two failures); known access denial (two methods/eight failures); readiness ordering (two methods/eight failures including one failed unwrap). These are **prototype regressions**, not claims that released/d3fa code had session-option bugs—it did not expose these options.
- Final signed `scripts/test-ios.sh --destination 'platform=iOS Simulator,id=9DBF4207-832B-4A34-88DB-AE841A6383DA'`: **611 XCTest +20 Swift Testing, zero failures**. Result `artifacts/test-results/IsoMe-20261114-124008-20349.xcresult`; log `artifacts/merge-readiness/shortcut-options-full-final.log`. No original assertion, selection, timeout, signing or Keychain setup was weakened.
- **15 Python localization tests**, full **2,611-active-key /nine-catalog /11-locale audit**, and **561 actual compiled Bundle lookups (51 keys ×11 locales)** pass. Five new keys/55 values were inserted; all2,415 existing entries and every original catalog byte are preserved, including the older description. Duration errors name the existing localized Stop after control. No native-speaker, localized editor/spoken or full-motion acceptance is claimed.
- Resource counterfactual: compile the **exact original d3fa catalog** with `xcstringstool`, then run the same checker; it fails `ar:Activity Profile: __MISSING_SMART_START__`. Not a second full app/runtime build.
- Actual compiled `extract.actionsdata` confirms optional Source/duration/profile, numeric duration, the three native enum cases, unchanged title/open behavior and all three simple phrases. This is registration metadata, **not execution in Shortcuts**.
- All **31 actual CI source-provenance commands** pass with their real per-job working directories. The actual Swift visit-reconciliation producer was rerun; all17 case outputs remain identical, only the two fixture copies' source hashes change. No hand-pinned hash.
- Android localization `--check` remains1,730 resources/ten locale packs; no generated Android translation changes. No Android runtime source changes or repeat of the unrelated million-record gate.

The first authoring build failed because adding a defaulted third argument did not satisfy the original protocol; an exact two-argument forwarding method restores it. A later authoring compile exposed an optional parameter shadowing the stored resolution closure; explicit `self` fixed it. Neither is a credential/environment regression. An early SQLite test passed assertions while deleting its directory before manager teardown; log inspection caught that fixture cleanup error. Stopping/releasing before removal produced a clean focused rerun and final session tests. Expected corrupt-store diagnostics in existing LaunchRecoveryTests are not relabeled as session failures.
