## Build and verify

Use JDK 17 and Android SDK 36. Set `ANDROID_HOME` or add your local SDK path to the ignored `local.properties` file.

```sh
cd android
./gradlew :domain:test :export:test :billing:test :geography:test :geography-assets:test :app:lintDebug :app:assembleDebug
./gradlew :data:connectedDebugAndroidTest
```

The second command runs isolated database tests on connected Android devices. It does not read the installed Whereday journal. Select a single device with `ANDROID_SERIAL` when more than one is attached. The debug APK is `app/build/outputs/apk/debug/app-debug.apk`; install using `adb install -r` to preserve the development app's history.

The isolated provider-identity regression includes one real document-picker selection of a uniquely named test-owned image. It releases its grant and deletes that exact image afterward; it never grants broad media access. Stop Argent helpers for the chosen device before native instrumentation, then substitute its explicit serial:

```sh
ANDROID_SERIAL=SERIAL ./gradlew :platform:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=com.bontecou.whereday.platform.PhotoIdentityTest
```

## Analytics implementation boundary

`UsageAnalyticsCore` defaults off and uses explicit persisted consent, per-consent/event UUIDs, a 50-event queue and immutable typed metadata. `captureConsent()` must run at the UI event boundary before launching asynchronous work; null, revoked and different-owner permits cannot later collect an event. Metadata and IDs are created only after a valid permit. Retried packets reuse saved bytes/IDs; duplicate suppression belongs to the receiver's existing event primary key. The private AtomicFile store bounds input/output to 64 KiB, rejects unknown/duplicate/malformed fields and requires an explicit disabled reset after storage corruption. Successful opt-out persists an empty disabled state before waiting for transport cancellation, preventing a crash during draining from restoring the old queue. A failed write inhibits this process and reports failure; it does not establish durable revocation.

AppGraph owns one controller, cancellable OkHttp transport and WorkManager scheduler. Settings → Usage analytics presents a separate explicit consent dialog; turning sharing off immediately inhibits collection, clears the persisted identity/queue and cancels only analytics jobs. Corrupt storage exposes a reset-to-off action, including when a build cannot send. Clearing journal data first revokes analytics through an application-owned operation. The onboarding entry appears only in configured builds; current visible-step and completion hooks collect only after consent. Permission requests/results and purchase/restore outcomes now retain the consent captured before the action; repeated completions are suppressed and finish events wait for their start event. Permission attempts lost during process/Activity recreation are dropped rather than assigned fresh consent. Real Play checkout and the broader Android/OEM consent matrix remain release checks. The separate local support log is never an analytics replay source.

Delivery defaults unavailable: `whereday.analyticsEnabled=false`. The production factory uses only the fixed Whereday Cloudflare `/v1/events` endpoint when explicitly enabled at build time; the optional `whereday.analyticsToken` is an extractable abuse-control key, not a mobile secret. Do not enable production sharing before deploying the local Android receiver patch and completing retention/privacy acceptance. No production analytics request was made during implementation. Tests use fake transports or a localhost MockWebServer. Missing configuration prevents approval, while a saved older preference can still be revoked.

HTTP redirects and implicit connection retries are disabled. Calls have a 10-second deadline, cancellation closes the owned call, and a bounded strict JSON receipt is required to acknowledge an event. Retryable statuses preserve exact saved IDs/payloads. WorkManager stores no identifiers or payloads in job input, requires connectivity, drains at most ten events per run, and uses unique one-time work plus 15-minute periodic recovery with backoff. Android scheduling can delay delivery. Production deployment, server retention, legal/store disclosures and release acceptance remain open.


Analytics event details: Android notification approval uses `authorized` only with the Android `notifications` request kind, avoiding a false location grant. Unknown pre-request Android permission state stays `unknown`; granting background location is not implied by foreground access. Only onboarding-originated permission requests enter this funnel. Export and webhook purchase surfaces report their own typed context. Only explicit Restore clicks create restore attempts; automatic purchase refreshes do not. Billing refresh results distinguish a newly verified entitlement from an offline cached grant, so cached access is never counted as fresh purchase/restore success. Configured SKU strings outside the reviewed allowlist are omitted from telemetry.


Onboarding now matches the iOS ready-page start choice: it defaults off and appears only with foreground/background location access. Permission state refreshes after runtime results and resume. The finish click freezes the chosen start, current permission status and analytics permit before dispatch; completion analytics uses that original permit after a successful save. Selecting immediate recording waits for the service acknowledgment before persisting setup. Failures remain visible on Ready, and users can turn the choice off to finish without recording. Cancellation before acknowledgment cannot commit setup; the small final save finishes even if its successful recomposition disposes the screen. Restoring a saved choice does not execute it. Notifications may remain denied; that does not imply background-location authorization. The dedicated-emulator recording path is verified; broader physical-device/OEM coverage remains open.

## Review history before importing

Choosing JSON, CSV or Markdown now prepares a private disk-backed review; it does not immediately mutate the journal. Review shows format, visit/point counts, date range, legacy locale/zone context, matching record count and bounded row errors. Invalid rows are excluded. Repeated identical source records are combined; conflicting values with the same source ID reject the file. Strict UTF-8 and supported timestamp ranges are checked before review.

The default policy keeps existing records. Replacing matching records requires a separate confirmation warning about local corrections/notes. Screen recreation resets that choice to keep-existing, requiring a fresh replacement choice. Matching uses record IDs, including deterministic IDs derived for legacy rows; semantic duplicates across different IDs/formats remain a separate reconciliation task. Replacement rechecks every relevant row against the preview snapshot inside the write transaction. If anything changed, the user must choose/review the file again. Existing point/session membership is retained. Closing a detector-owned visit also releases its dwell ownership.

Imports are application-owned and remain visible after screen/Activity recreation. Process death drops the review and never restarts an import. Cancel interrupts provider reads/parsing and fences stale work; even an uncooperative provider cannot publish a late review or block journal clearing. Such a provider may retain its own resources until it cooperates. During writes, a cooperative token is checked inside one atomic transaction. Cancel before its final decision rolls back; a later cancel shows actual committed counts. Clear all journal data blocks new imports, drains an approved write and discards old reviews before the actual clear completes.

The former **25 MB file cap is removed**. Input is streamed to private disposable disk storage and parsed into an indexed review. Storage availability and individual-record size still constrain imports; no unlimited-resource claim is made. Crash-at-commit recovery acceptance, more document providers, physical iOS↔Android round trips, expanded mapping/semantic duplicate handling, localization/accessibility and release memory budgets remain open. No source URI is retained, and no import contents are sent to analytics or replayed automatically.

## Incremental history parsing foundation

`HistoryImporter.scan(reader, format, ..., onVisit, onPoint)` consumes JSON, CSV and Markdown incrementally. It retains the current record/field rather than the complete document or previous records. JSON reads known scalars directly and skips unknown structured metadata; CSV emits RFC4180 logical rows across arbitrary reader chunks; Markdown keeps only the current table/legacy visit section. The caller owns the reader. Sink failures and cancellation propagate, and emitted records remain provisional until scan completion validates EOF; a staging sink must discard emissions after failure.

The compatibility `parse(text, ...)` API collects from this same reader path and still returns lists. The production import controller now uses `scan` directly with disk staging. Diagnostics retain only the first ten messages, each bounded to 200 characters, with an exact separate `rejected` count used by import review. Duplicate known JSON fields/subject arrays and duplicate CSV columns are rejected; malformed JSON/trailing content cannot report successful completion. Retained text per logical record is limited to 256 Ki UTF-16 code units, including format-specific names/metadata overhead, with at most 256 columns. Known JSON scalars are bounded before materialization; unknown values are skipped incrementally. Oversized records fail the review instead of being silently omitted.

`./android/gradlew -p android :export:streamingImportBudgetTest` runs a dedicated 96 MiB JVM. It lazily generates and consumes one million records in **each** supported format (67 MB JSON, 28 MB CSV and 36 MB Markdown), verifies every timestamp/count and proves the first record is emitted before the file is exhausted. CI runs this separately from the ordinary format suite and saves its XML report. This is a parser memory contract, not an Android device or end-to-end import budget.

The picker now streams source bytes to an app-private scratch file, detects format with a separate reader pass, validates strict UTF-8 during capture, and inserts provisional records into a disposable SQLite index. Each encoded staged record is limited to 1 MiB. The index buffers and pages at most 200 records and 1 MiB of payload, detects identical/conflicting source identities across flushed batches, and rejects oversized encoded records. Existing journal matches are measured in SQLite before loading: groups above 512 KiB of text split recursively, and a single match may contain at most 1 MiB of text. The raw file is deleted after successful parsing. Review retains only counts/range/context and bounded diagnostics in memory.

Matching inspection runs against one history snapshot and stores SHA-256 fingerprints of complete matching rows, including session membership and correction/country metadata, alongside staged records. A sealed checksum covers source values, identities and baselines. Approval verifies that checksum and processes bounded batches in one Room write transaction. Replacement checks the current fingerprint before each write; a stale later batch rolls back earlier batches. Keep-existing uses current database matches, preserving changes made after review. Point replacement retains its session, and closing a detector-owned visit releases dwell ownership. A second stage verification and cancellation check precede the commit decision.

Private staging lives under `cache/history-import-review`, outside the FileProvider export root. Completion, discard and cancellation close/delete owned scratch files. Clear waits for approved writes and local staging cleanup before clearing the journal. Provider cancellation is separate, so an uncooperative external read cannot block clear or publish a later review. Factory reconstruction best-effort reaps inactive abandoned workspaces; create/clear retry cleanup strictly, while the process registry protects live reviews. Process death drops review authority and never restarts an import. Scratch SQLite uses no cross-process resume journal; corrupt leftovers are discarded.

The former 25 MB total-file guard is no longer used. Scratch open/write/flush/close failures abort review and release owned resources. SQLite-full tests constrain only disposable test databases and verify atomic rollback with an existing sentinel preserved. Actual physical-device memory, SQLite cursor/window behavior and storage budgets remain acceptance work. Native regression and large-file instrumentation use disposable platform-test storage; they do not replace purchased/physical transfer, OEM or crash-at-commit acceptance.


## Visit reconciliation

New detector arrivals close older open visits at the detected arrival and merge with the first chronological nearby stop when the iOS duplicate rules match: at most 100 m apart, and either arrivals within fifteen minutes or interval gap at most thirty minutes. Android uses ellipsoidal platform distance at this boundary. The surviving visit keeps its identity, coordinates, corrections and country metadata; missing names/addresses are filled and distinct nonempty notes are combined. If either visit is open, the merged visit remains open. Detector ownership transfers to that survivor so later departure updates the retained record.

App startup also repairs multiple open visits, retaining the latest open arrival and inferring earlier departures from the next strictly later arrival. It then merges duplicates chronologically in one transaction using paged reads and conservative spatial/time prefilters. Equal-arrival ties use IDs for stable ordering; iOS does not specify that tie. Cancellation or write failure rolls back closures, merges and detector remapping. A failed startup repair reports a fixed local log event and message. The import review still matches source identities; this subsequent visit repair does not introduce semantic point deduplication.

`python3 android/scripts/generate_visit_reconciliation_fixtures.py` executes the current Swift matching/gap/merge/inferred-departure method bodies and constants with synthetic model adapters. Fourteen cases verify represented fields and Android distance decisions. `--check-source` checks source/harness/generator provenance and the native fixture copy. The adapters do not prove SwiftData persistence, every iOS-only model field, physical visit calibration, passive detection or release performance. Those remain separate acceptance work.

## Google Play reviews

`whereday.playReviewEnabled` defaults to `false`. Automatic prompting also requires a Google Play installer, completed onboarding, a resumed and focused Activity, use on two distinct local civil days, and one verified manual file export. After a one-second delay, the controller prepares the Play flow and durably consumes a single attempt before launch. Concurrent callers cannot launch twice; cancellation, focus loss and journal clear fence late preparation. Only two dates and two milestone flags are stored locally, independently of analytics consent. Journal clear removes eligibility dates/export state while preserving the consumed attempt. Unreadable state fails closed; review failures never invalidate a delivered file.

Verified SAF saves and default-folder exports count. Preview, preparation, failed writes, scheduled output and opening the share chooser do not count; Android does not provide reliable recipient-completion evidence for generic sharing. This is a documented difference from the iOS completed-share hook. An attempt reserved before focus loss or process death remains consumed, preventing repeated prompts.
