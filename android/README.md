Application UI instrumentation uses the separate `mapQa` package, `com.bontecou.whereday.mapqa`: run `:app:connectedMapQaAndroidTest`, never target the installed main application. Gradle/UTP uninstalls an application's target during cleanup. An October 27 QA run against the main package deleted its prior 13 points; recovery remains unresolved. Library instrumentation targets remain isolated test applications. Use `adb install -r` for ordinary updates of the owner's debug app.

## Build and verify

Use JDK 17 and Android SDK 36. Set `ANDROID_HOME` or add your local SDK path to the ignored `local.properties` file.

```sh
cd android
./gradlew :domain:test :export:test :billing:test :geography:test :geography-assets:test :app:lintDebug :app:assembleDebug
./gradlew :data:connectedDebugAndroidTest
```

Application UI test selection is defined in [the Android workflow](../.github/workflows/android-tests.yml). Run `CurrentLocationFlowTest` on its own fresh `mapQa` installation: it grants location permissions to the disposable package, and those grants outlive individual tests. The main UI selection deliberately excludes it so denied-permission recording, launcher and automation checks remain meaningful. Revoking runtime permissions inside the same instrumentation process can terminate that process. System-permission classes also run separately. Install the synthetic automation companion before transport checks and remove it afterward.

The second command runs isolated database tests on connected Android devices. It does not read the installed Whereday journal. Select a single device with `ANDROID_SERIAL` when more than one is attached. The debug APK is `app/build/outputs/apk/debug/app-debug.apk`; install using `adb install -r` to preserve the development app's history.

For a task-owned emulator, `scripts/run_qa_instrumentation.py` can execute the same native AndroidJUnitRunner APKs without Gradle discovering other attached devices. Build the selected APKs first. Supply the exact AVD name, emulator serial, expected test count and a fresh evidence directory; the runner verifies APK/target identities, refuses installed QA packages, validates every reported case and removes its disposable packages afterward. It accepts only the mapQa application or isolated data/platform test packages, never a physical device or the main app. Native tests require exclusive use of the selected AVD, with no active inspection helper.

```sh
python3 scripts/test_qa_instrumentation.py
python3 scripts/run_qa_instrumentation.py \
  --adb "$ANDROID_HOME/platform-tools/adb" \
  --aapt2 "$ANDROID_HOME/build-tools/35.0.0/aapt2" \
  --serial emulator-5588 --avd whereday-YOUR-OWNED-QA-AVD \
  --server-port 5049 --module app \
  --classes com.bontecou.whereday.VisitOverlapFlowTest \
  --expected-tests 9 --output /absolute/fresh/evidence-directory
```

`--server-port` defaults to 5037; use another port only for a separately established task-owned ADB server. It does not start or reset a server or emulator. Do not stop a shared ADB server to repair one device. A local run's `verification.json` proves only the explicitly selected tests and APK hashes, not the complete release suite.

The isolated provider-identity regression includes one real document-picker selection of a uniquely named test-owned image. It releases its grant and deletes that exact image afterward; it never grants broad media access. ```sh

- `geography`: bounded worldwide geographic time-zone queries with original per-polygon precision and a small geometry cache.
- `geography-assets`: build-only conversion/fidelity checks for the pinned Timeshape source database; generated assets include provenance and do not go in Git.

- `app`: Compose onboarding, dated map queries, exact/inferred outing details, visit and saved-place editors, Country Days/manual stays, export preview/import and settings.

### Road request ownership

`RoadDisplayService` now provides serial, ephemeral preparation over the road rules. It defaults to unavailable and admits a request only when configuration, explicit enablement, network policy, foreground visibility and journal readiness are all supplied as true. Each access change invalidates prior tickets, cancels owned child jobs and drops the memory cache. Source fingerprints distinguish route inputs, and consumers must call `isCurrent(plan, currentSourceFingerprint)` before rendering a retained plan. RoadDisplayController connects activity-owned sessions, persisted road policy and the application journal-clear barrier as described below. The domain service itself does not observe Android systems.

Clear fences admission before cancellation/join and discards access updates made during maintenance. It waits for actual worker completion, including when the original caller was canceled, and requires fresh admission afterward. Overlapping clears retain their fence until all finish. Provider callbacks cannot invoke maintenance and join their own request. The application clear coordinator now awaits every session worker before resetting road consent and continuing journal erasure.

Defaults serialize provider attempts at least 250 ms apart, with a 10-second attempt timeout and a 60-second total preparation timeout including queue wait. A timed-out attempt may use the alternate transport; total timeout and caller cancellation abort preparation. These are cooperative coroutine deadlines: the Geoapify HTTP adapter cancels its underlying request and bounds decoding; timeouts cannot forcibly stop arbitrary blocking or non-cooperative code. See the [coroutines timeout contract](https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-core/kotlinx.coroutines/with-timeout-or-null.html).

Accepted response geometry is capped at 20,000 coordinates per response and 50,000 cumulatively per preparation; hitting a geometry limit stops further provider attempts and retains raw fallback segments. The memory LRU retains at most four routes and 50,000 coordinates, with cache hits expiring after ten minutes and on elapsed-clock rollback. Large results can be shown without being retained in the cache. Explicit refresh bypasses a cached result. Cache copies protect later consumers from mutation, and failures expose typed warning identities rather than arbitrary provider exception text. No cache is persisted to disk. Actual response decoding limits, provider caching terms, rendering budgets and on-device memory/latency still require implementation/acceptance.
