# Native source and notice review

Reviewed October 30, 2026. This is an engineering source/attribution review, not legal approval or a reproducible rebuild of the upstream binaries. `legalReviewComplete` must remain false. The parent package-provenance verifier separately checks which selected AAR native binaries actually reach the APK/AAB; finding native code inside an inspection JAR does not prove it ships.

## AndroidX native inputs

**Graphics Path.** Its [CMake definition](https://android.googlesource.com/platform/frameworks/support/+/8a05a22af450d589ef911d772a001a49dcb05b71/graphics/graphics-path/src/main/cpp/CMakeLists.txt) compiles `Conic.cpp`, `PathIterator.cpp` and `pathway.cpp`. Those three implementation files, the four path/conic/scalar headers and all three files in `math/` have AOSP Apache 2.0 headers. In particular, the Filament-namespaced `math/vec2.h`, `TVecHelpers.h` and `compiler.h` carry Apache headers. This inspected source set supplies no evidence for adding a guessed Skia BSD notice merely because the library handles path geometry. The canonical Apache text already packaged is relevant; this observation does not audit compiler/runtime object code. [Native tree](https://android.googlesource.com/platform/frameworks/support/+/8a05a22af450d589ef911d772a001a49dcb05b71/graphics/graphics-path/src/main/cpp/), [math tree](https://android.googlesource.com/platform/frameworks/support/+/8a05a22af450d589ef911d772a001a49dcb05b71/graphics/graphics-path/src/main/cpp/math/).

**DataStore.** The [release build definition](https://android.googlesource.com/platform/frameworks/support/+/de4cda56f812357e582b3e1aa32bc737636614a2/datastore/datastore-core/build.gradle) compiles a shared-counter library and statically incorporates it into `datastore_shared_counter`. Its `shared/shared_counter.cc`, `jni/androidx_datastore_core_SharedCounter.cc` and `shared_counter.h` all carry AOSP Apache 2.0 headers; the build enables upstream linker stripping. No separately vendored third-party source library is named in these compilation inputs. Toolchain/system headers and statically linked runtime contributions still need a separate check. [Shared source](https://android.googlesource.com/platform/frameworks/support/+/de4cda56f812357e582b3e1aa32bc737636614a2/datastore/datastore-core/src/androidMain/cpp/shared/shared_counter.cc), [JNI source](https://android.googlesource.com/platform/frameworks/support/+/de4cda56f812357e582b3e1aa32bc737636614a2/datastore/datastore-core/src/androidMain/cpp/jni/androidx_datastore_core_SharedCounter.cc).

**SQLite Bundled.** The [2.6.2 build definition](https://android.googlesource.com/platform/frameworks/support/+/fe30df161d480829efb21f37ff67a9f8cac9c620/sqlite/sqlite-bundled/build.gradle) explicitly selects SQLite **3.50.1**, release year 2025, compiles its amalgamation and statically incorporates it into the JNI library; Android adds an atomic-library link. It explicitly records SQLite's public-domain status and the AndroidX Apache wrapper distribution. The selected ARM64 AAR binary contains the matching `3.50.1` string and source identifier `2025-06-06 14:52:32 b77dc5e0f596d2140d9ac682b2893ff65d3a4140aa86067a3efebe29dc914c95`. String correspondence supports the version association but is not a full source-to-binary proof. [SQLite's own copyright policy](https://www.sqlite.org/copyright.html) distinguishes deliverable library code from separately licensed test/documentation material; do not package the latter by assumption.

## MapLibre: concrete aggregate-notice gaps

The current pinned `maplibre-android-13.4.1.txt` contains many native notices, including FreeType, expected-lite, Boost, geometry, FSST, FastPFOR and SIMDe. It is nevertheless not an exhaustive list of the exact tag's declared native inputs. The [root CMake file](https://github.com/maplibre/maplibre-native/blob/18545ca10d296704b2cba675b182ff2c8da24588/CMakeLists.txt) links `mbgl-core` to PMTiles, `unordered_dense`, `mlt-cpp` and conditional HarfBuzz/FreeType. HarfBuzz and unordered containers default on in this source. The [Android platform definition](https://github.com/maplibre/maplibre-native/blob/18545ca10d296704b2cba675b182ff2c8da24588/platform/android/android.cmake) also links bundled ICU, bundled SQLite and `MapLibreNative::Base::jni.hpp`.

The selected published AAR now supplies authoritative configuration metadata: [preserved `javap -constants` output](../captures/native-notices-20261030/maplibre-build-config.txt) reports `GIT_REVISION=18545ca10d296704b2cba675b182ff2c8da24588`, `FLAVOR=vulkan`, `BUILD_TYPE=release` and `MAPLIBRE_VERSION_STRING=MapLibre Android/13.4.1`. This is stronger than inferring the backend from a Maven name. The [Android Gradle file](https://github.com/maplibre/maplibre-native/blob/18545ca10d296704b2cba675b182ff2c8da24588/platform/android/MapLibreAndroid/build.gradle.kts) associates the Vulkan flavor with `MLN_WITH_VULKAN=ON`. The package verifier separately connects the selected AAR bytes to shipped native files. These facts identify the declared revision/backend, but do not prove all compiler flags, static dependencies, source reproducibility or legal completeness. Preserve designated originals conservatively while keeping those limits explicit.

## Boundaries and remaining work

- MapLibre separately bundles SQLite **3.45.3** at this source revision, independently of AndroidX's **3.50.1**. Its [SQLite CMake](https://github.com/maplibre/maplibre-native/blob/18545ca10d296704b2cba675b182ff2c8da24588/vendor/sqlite.cmake) compiles the [vendored amalgamation](https://github.com/maplibre/maplibre-native/blob/18545ca10d296704b2cba675b182ff2c8da24588/vendor/sqlite/src/sqlite3.c), whose header identifies 3.45.3 and carries the public-domain blessing. Do not merge these two native SQLite implementations in provenance reports.
- The source tree declares filesystem, Tracy and WebGPU dependencies too. Mere presence in `vendor/` or an exported target list is not evidence they all ship in the selected Android backend. For example, the inspected [Android/default filesystem implementation](https://github.com/maplibre/maplibre-native/blob/18545ca10d296704b2cba675b182ff2c8da24588/platform/default/src/mbgl/util/filesystem.cpp) uses standard/POSIX behavior; this review has not established that gulrak/filesystem contributes Android object code. Do not add a false shipped-dependency claim from directory discovery alone.
- The aggregate already includes the designated FreeType license, expected-lite, Boost and many native-base dependencies. Presence still needs exact-version/copyright comparison and complete relevant individual-file review. HarfBuzz's own COPYING expressly points to potentially additional subdirectory and individual-file notices. Conservatively including its top-level file does not close that review.
- Compiler-rt, libc++/libc++abi, atomic support and other statically incorporated toolchain pieces remain a separate unresolved source/build correspondence and notice check. Package `DT_NEEDED` entries cannot identify every statically incorporated contribution. The app's local NDK used to strip dependency bytes does not by itself identify upstream publishers' compilation toolchains.
- This research narrows concrete packaging omissions and distinguishes selected-source evidence from actual shipment. It does not approve all source licensing, legal obligations, toolchain contents, binary reproducibility or release acceptance.
